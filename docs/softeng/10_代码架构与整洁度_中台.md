# 代码架构与整洁度 · 中台补充规范

> **上级正本（强制）**：工作区 `AI开发规范/软件工程规范/代码架构与整洁度强制规范.md`  
> **本文件**：财务共享中台 Agent 的项目补充；与正本冲突时以**更严**者为准。  
> **生效**：所有本仓 `backend/` `frontend/` `deploy/` `tests/` 变更。

---

## 1. 分层与单向依赖

```text
frontend (Vue)
  → HTTP only
backend routes / api
  → services（auth, grant, skill, chat, sync, audit）
  → adapters（oc_client, git_skills, storage）
  → models / db
```

- **禁止**：route 内写长业务；Vue 内算财务金额/权限真相。  
- **禁止**：`oc_client` 被前端间接暴露（无 OC 绝对 URL 下发浏览器）。  
- **OpenCode**：仅 `oc_client` 模块访问；其它模块不得散落 `httpx` 打 OC。

---

## 2. 会话与隔离（硬）

- 每个 `ChatSession` 必须绑定 `user_id` + `opencode_session_id`。  
- 读消息、续聊、列附件：服务端校验归属；admin 审计另开权限点。  
- 工作目录：`data/workspaces/{user_id}/{session_id}/`，禁 `..` 与绝对路径穿越。  
- **禁止** 全局共享一个 OC session。

---

## 3. Skill 与授权

- 一期运行过滤：`visibility == published` **且** Grant 命中（或 admin）。  
- 状态机：`private → pending → published → disabled`；非法跳转拒绝。  
- 公开仓同步：仅 `published` 可 push；pull 后校验 `catalog.yaml`。  
- skill id / version / content_hash：运行记录钉扎，禁止静默换版。

---

## 4. 安全与秘密

- 密码：哈希存储（实现选定算法写 MADR）；日志禁止明文密码与 API Key。  
- `.env`、`opencode.json` 中的 key、数据库文件：**gitignore**。  
- 审计：登录、授权变更、审批、同步、用户 CRUD、敏感配置变更必记。

---

## 5. API 风格

- 前缀 `/api/v1/`。  
- 错误：稳定 `code` + 人话 `message`；未登录 401；无权限 403；冲突 409。  
- 列表接口默认按当前用户过滤；admin 全量须显式权限。

---

## 6. 前端（Vue）

- 目标：简洁、靠拢利润看板（顶栏、卡片、主色层级），**不复制看板业务组件**。  
- 组件：展示与交互状态；鉴权结果以 API 为准。  
- 禁止把 OC 或 DB 连接信息写进前端环境公开变量。

---

## 7. 测试与门禁

- 行为变更：先红后绿。  
- 必测类：越权（A 读 B 的 chat）、未授权 skill 不可见、路径穿越、同步 dry-run。  
- 门禁：`sh tests/run_verify.sh; echo EXIT:$?` —— 真实退出码。

---

## 8. 命名与文件

- Python：`snake_case` 模块；服务类后缀 `Service`；OC 适配仅 `oc_client.py`（或包）。  
- Vue：组件 `PascalCase.vue`。  
- 一个概念一个真相源：Grant、SkillVisibility、AuditAction 用枚举/常量单点定义。

---

## 9. 与看板整洁规范的关系

| 看板特有 | 中台 |
|----------|------|
| 前端零金额运算 / 分整数 | 无经营利润公式；**权限与会话隔离**是硬核 |
| ECharts 诚实尺度 | 对话与任务状态诚实（加载中≠0 条） |
| run_verify 大体量 | 从轻门禁长到同等严肃 |

工作区整洁规范 **全文适用**；本文件只补中台特有边界。
